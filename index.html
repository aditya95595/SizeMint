IMAGE COMPRESSION, EXPLAINED

Why compress to a target size?

Many upload forms, profile systems and document portals impose a maximum file size. A modern phone photograph can easily exceed that limit because it contains millions of pixels and a lot of visual detail. The useful question is often not “what quality percentage should I use?” but “how small does this file need to be?”

SizeMint takes the second approach. You choose a byte target and the browser tries different encoder settings and, when necessary, smaller dimensions. The tool reports the final file rather than pretending every image can meet every target.

JPG, WebP or PNG?

JPG

A broadly supported lossy format that is well suited to photographs. Strong compression can create blockiness or ringing around fine details.

WebP

A modern web-friendly format that often gives a useful size/quality balance for photographs and general images.

PNG

Lossless and useful for transparency, screenshots, diagrams and graphics. It can be much larger than JPG/WebP for photographs.

AVIF input

SizeMint accepts AVIF input when the browser can decode it. Output choices are WebP, JPG or PNG.

How to choose a sensible target

Start from the destination. If a form says “maximum 100KB,” use 100KB. If you are preparing a website image, consider the display dimensions first and then choose a format and quality that preserve the important details. A tiny avatar does not need the same resolution as a large hero photograph.

For difficult targets, reducing dimensions can be a better trade-off than pushing quality extremely low. The best setting is the smallest file that still looks good at its actual display size.

What happens inside your browser?

The compressor uses standard browser image APIs to decode the selected file, draw it to a canvas and encode candidate results. It compares candidate sizes against your target and can iterate through quality and dimensions. The resulting Blob is then offered directly for download.

Privacy by design

The core compressor does not need a SizeMint image-upload endpoint. Selected images are processed in the browser during normal use. Website hosting and optional third-party services can still process ordinary web-request or advertising information; see the Privacy Policy for the current disclosure.

FAQ

Questions people have before compressing an image

Does SizeMint upload my images?

No. The core compressor is designed to read and encode the selected image in your browser. It does not require an image-upload endpoint.

Can SizeMint guarantee an exact file size?

No. File size depends on image content, dimensions, browser encoders and format. SizeMint aims for a result at or below your target where possible and reports when it cannot reach it.

What happens if the target is too small?

The compressor tries progressively smaller dimensions and encoder settings. If the target still cannot be reached, the result is marked as best effort so you can decide whether the trade-off is acceptable.

Why can PNG be difficult to shrink?

PNG is lossless and its quality parameter does not work like JPEG/WebP quality. Photographs often become much smaller when encoded as JPG or WebP, provided the destination accepts those formats.

Can I compress several images at once?

Yes. Select multiple supported images. SizeMint processes them individually in your browser and can package successful results into one ZIP.

Can I reduce image dimensions?

Yes. Set a maximum width. If a target remains difficult, the compressor may also reduce dimensions as part of its best-effort search.

What is the input limit?

Each selected file can be up to 25MB. Very large pixel dimensions are also limited to reduce excessive browser memory use.

Does compression overwrite my original?

No. The original file is not replaced. SizeMint creates a separate result for download.

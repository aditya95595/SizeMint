SIZEMINT GUIDES

Practical image-compression guides.

Image compression is not simply a matter of choosing the lowest quality setting. The best result depends on the original dimensions, the image format, where the image will be used and the file-size limit you need to meet. These guides explain the decisions in plain language.

How to compress an image to 100KB

A 100KB limit is common for forms, profile pictures, document portals and other upload workflows. Start by checking the original image dimensions. A very large photograph may contain far more pixels than the destination actually needs, so reducing width can preserve better visual quality than aggressively lowering encoder quality.

Step 1: choose the 100KB target

Open the SizeMint compressor and select 100KB. If the image is already below that limit and you do not need to change its format or dimensions, there may be nothing to gain from recompressing it.

Step 2: choose a suitable format

For photographs, WebP or JPG is usually more practical than PNG when a small file is the priority. PNG is lossless and can remain large for detailed photographs. If the image contains transparency or needs lossless storage, PNG may still be the right choice even when the target is harder to reach.

Step 3: reduce dimensions when necessary

If the image is several thousand pixels wide, try setting a maximum width appropriate for its final use. A profile image or form upload rarely needs the full resolution of a modern phone camera. Smaller dimensions can reduce both the number of pixels and the amount of detail the encoder has to store.

Step 4: inspect the result

Do not judge the result only by the byte count. Open the downloaded image at its intended display size and check faces, text, edges and fine details. If the result is visibly degraded, increase the target or use a larger maximum width and accept a somewhat larger file.

JPG vs WebP vs PNG: which should you choose?

JPG is a long-established choice for photographs. It is supported almost everywhere and handles continuous-tone images well, but repeated saves and strong compression can create visible artifacts around edges and fine detail.

WebP is a modern image format designed for efficient web delivery. It supports lossy and lossless compression and is often a useful default for photographs when the software receiving the file accepts it.

PNG is lossless and supports transparency. It is particularly useful for screenshots, diagrams, logos and graphics where crisp edges or exact pixel values matter. For ordinary photographs, however, PNG can be substantially larger than a lossy format.

When you are unsure, start with automatic output for a photograph and compare the result. If the destination explicitly requires JPG or PNG, choose that format rather than relying on automatic conversion.

How to reduce image size without making it look bad

There are three main levers: dimensions, format and compression quality. Changing all three aggressively at once makes it difficult to understand why an image became blurry or blocky.

  • Start with dimensions. Match the maximum width to the actual display or upload requirement.
  • Choose the right format. Use a lossy format for photographs when the destination permits it; use PNG when lossless output or transparency matters.
  • Use moderate quality. Lower quality gradually and inspect important details rather than choosing the lowest possible value.
  • Compare at real size. An image that looks soft when zoomed to 300% may look completely fine at the size visitors actually see.
  • Keep an original. Compression is usually a one-way operation. Keep the original file if you may need to edit or export it again later.

Why some images refuse to reach a small target

There is no universal relationship between dimensions and file size. A simple illustration with large flat areas can compress extremely well, while a noisy photograph with foliage, hair or texture may require more bytes to preserve similar detail. Browser encoders also have their own limits and behavior.

For that reason, a responsible compressor should report when a target could not be reached instead of claiming an exact result. SizeMint may reduce dimensions when necessary, but it still reports the final size so you can decide whether the trade-off is acceptable.
